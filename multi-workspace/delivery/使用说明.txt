DSH 多文件夹工作区
插件名称：dsh-multi-workspace
版本：1.0.0

一、它提供什么
1. 创建工作区时可以一次选择多个文件夹：第一个是主文件夹，其余是成员文件夹。
2. 工作区下的所有会话（包括子任务）都能通过绝对路径访问全部成员文件夹。
3. 已有工作区可以从工作区行的“...”菜单进入“修改工作区”，改名、添加或移除成员文件夹。
4. 原生工作区行为保持不变：会话 cwd、@file 补全、右侧文件树仍以主文件夹为准。
5. 工作区与成员文件夹的对应关系保存在 <DSH_HOME>\multi-workspace\state.json；删除工作区不会删除任何文件夹或文件。
6. 创建、修改和目录浏览采用独立 DSH 蓝青色工作台界面，支持深浅主题与窄窗；工作区信息和文件夹分区展示，目录数量一目了然，每行显示文件夹名称与完整路径。

二、适用范围
Windows 64 位的 DeepSeek Harness Desktop。DSH 版本范围以 plugin/package.json 的 engines.dsh 为准，当前锁定 0.2.1-rc.2。
插件已预构建，不要求另外安装 Node、Python 或 npm 包；安装使用目标 DSH 自带的命令行和运行时。
不要把整个 .dsh 或别的机器上的链接路径覆盖到目标机器。

三、安装
1. 把整个 ZIP 解压到任意普通目录，不能直接在压缩包预览窗口里运行。
2. 完全退出 DSH，包括托盘图标。脚本不会擅自结束进程。
3. 可先双击“检查环境.cmd”；它只报告路径、插件包和运行状态，不修改设置。
4. 双击“安装.cmd”，等待显示 Install complete，再打开 DSH。
5. 安装后：在“添加工作区”时可以选择多个文件夹；已有工作区行的“...”菜单会出现“修改工作区”。

安装器把插件复制到：
  <DSH_HOME>\custom-plugins\dsh-multi-workspace\<profile>
默认 DSH_HOME 是当前用户的 .dsh（C:\Users\<用户名>\.dsh），默认 profile 是 desktop。
安装完成后可以移动或删除解压目录；已安装插件不依赖解压目录，更不依赖打包机器。
包管理操作明确使用离线模式；离线条件不满足时会报告失败并回滚，不会静默改为联网下载。

四、卸载
完全退出 DSH（含托盘图标），双击“卸载.cmd”。
它只移除此 profile 中的 dsh-multi-workspace，保留其他插件、模型与会话设置，也不会删除任何工作区文件夹或其中的文件。
卸载后多文件夹工作区能力消失；DSH 原生工作区与主文件夹记录仍由 DSH 自己维护。

五、检查环境
双击“检查环境.cmd”，或运行 tools\portable.ps1 -Mode Check。
它只显示：DSH CLI 路径、DSH_HOME、profile、插件安装目录、插件版本、当前是否已注册、DSH 进程数量。不修改任何文件或设置。

六、如何创建多文件夹工作区
1. 打开 DSH 的“添加工作区”入口（可按 Ctrl+O，或点击工作区列表中的“添加工作区”）。
2. 在弹出的“创建工作区”对话框里填写“工作区名称”（留空时用第一个文件夹的名字）。
3. 点击“添加”选择第一个文件夹；加入后它是主文件夹（第一行带“主文件夹”徽标）。
   在 Windows 桌面版中，“添加”优先打开 Windows 原生“Select Workspace Directory”文件夹选择器：一次选择一个文件夹，选中后自动加入列表。
4. 再次点击“添加”继续选择其他文件夹，可反复多次；每点一次“添加”加入一个文件夹。
5. 文件夹列表可以拖动重排：默认第一项是主文件夹，拖动改变顺序后，新的第一项自动成为主文件夹。
6. 需要时点击某行右侧的“×”删除文件夹（主文件夹也可以删除）；删除主文件夹后，下一项自动成为主文件夹。
7. 只有以 Web/浏览器方式打开 DSH（没有原生目录选择器）时，“添加”才改用插件内置的文件夹浏览器：面包屑 + 路径输入 + 返回上级 + 目录列表，可在当前目录勾选多个子文件夹后点“添加所选”，隐藏文件夹默认隐藏、底部可切换显示。
8. 然后点击“创建”。创建后 DSH 会打开该工作区：会话可以读取所有成员文件夹；写主文件夹之外的内容需要逐次批准（见第八节）。
   外观说明：创建/修改对话框采用蓝青色工作台设计，工作区信息与文件夹区域分开展示，文件夹列表显示目录数量、名称、完整路径与主文件夹徽标，支持深浅主题与窄窗。

七、已有工作区：改名、添加或移除成员文件夹
1. 在左侧工作区列表中，把鼠标移到目标工作区行，点击行尾的“...”按钮。
2. 原生“重命名/删除”菜单里会多出“修改工作区”，点击它。
3. 在“修改工作区”对话框里改名、添加或移除成员文件夹（“添加”的选择方式与创建时相同，见第六节第 3–4、7 步），点击“保存”。
4. 修改工作区时主文件夹是固定的：DSH 工作区目录不能在修改对话框里更换，也不能在这个对话框删除主文件夹（要换主文件夹请新建工作区）；改名只改工作区显示名，不会移动文件夹。

八、权限与审批（请读清楚）
1. 读取：DSH 的读操作不受沙箱限制，会话可以直接读取成员文件夹。
2. 写入/修改：DSH 0.2.1-rc.2 的沙箱只有单一可写根（主文件夹）。模型要写成员文件夹时，会通过 DSH 原生 sandbox_permissions 提权请求，由你逐次批准。
3. 本插件不会自动提升权限，不会改会话的 sandbox mode，也不会静默改为 danger-full-access。
4. 建议把需要频繁改写的文件夹放在主文件夹，或接受逐次审批。

九、已知限制
1. 跨文件夹写/改需要 DSH 提权审批（逐次）；读免费。
2. @file 补全、右侧文件树、变更面板仍只看主文件夹；模型用绝对路径工具访问其他文件夹。
3. 版本锁定：本包只针对 DSH 0.2.1-rc.2 适配；依赖该版本的 slot 名、CSS 类与 DOM 结构，升级 DSH 后可能需要重新适配。
4. 不修改 DSH 的 app.asar，不注册新的 session event，不改工作区注册表，也不做文件系统符号链接映射。
5. “修改工作区”入口通过增强“...”原生菜单实现，属 DOM 增强；DSH 前端结构大改时该入口可能暂时失效。
6. 工作区改名不会改变任何文件夹；删除工作区不会删除文件夹或文件。

十、备份与回滚
安装/卸载前会在 <DSH_HOME>\backups\dsh-multi-workspace\时间戳-编号 生成事务备份：
  - profile 的 package.json、pnpm-lock.yaml、pnpm-workspace.yaml、cordis.patch.yml 等元数据副本；
  - 原插件目录或 node_modules 链接的副本；
  - transaction.json（本次事务清单）和成功时的 result.txt。
失败时安装器自动回滚本次事务；若自动回滚也失败，会输出备份路径。人工恢复时请针对性地恢复本插件相关项，不要把旧备份整套覆盖到后来已经改过的 profile，否则可能覆盖之后添加的其他插件设置。
成功事务的备份会保留，可定期手工清理较早的时间戳目录。

十一、自定义 DSH 路径、DSH_HOME 或 profile
如果未能自动识别 DSH，或想安装到别的 profile，在 PowerShell 中进入解压目录执行（路径含中文或空格时保留双引号）：
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\portable.ps1 -Mode Check -DshPath "D:\Apps\DeepSeek Harness" -DshHome "D:\DSH Data" -Profile desktop
确认路径正确后，把 Check 改成 Install；卸载使用 -Mode Uninstall。
参数说明：
  -DshPath   DSH 安装目录，也可以直接指向 DSH 自带的 dsh.cmd；
  -DshHome   DSH 数据目录，默认 %USERPROFILE%\.dsh；
  -Profile   profile 名称，默认 desktop。
三个 cmd 也接受同样参数，例如：
  安装.cmd -DshHome "D:\DSH Data" -Profile desktop
已有 profile 必须先由 DSH 初始化；安装器不会创建或覆盖整套个人配置。

十二、交付文件清单
交付包名：dsh-multi-workspace-1.0.0-win-x64.zip。
使用说明.txt、安装.cmd、卸载.cmd、检查环境.cmd、tools\portable.ps1、SHA256SUMS.txt，以及预构建插件 plugin\：
  plugin\package.json、plugin\cordis.patch.yml、plugin\lib\index.js、plugin\lib\client.js、

ZIP 旁的 .sha256.txt 是整个压缩包的校验值；包内 SHA256SUMS.txt 用于逐个校验交付文件。

十三、常见问题
1. 提示 DSH 正在运行：完全退出 DSH（含托盘图标）后重试；脚本不会替你结束进程。
2. 提示找不到 DSH：先启动一次 DSH Desktop，或用 -DshPath 指定安装目录/dsh.cmd。
3. 提示路径是重解析点：安装器为避免操作链接指向的其他目录而停止；请选择普通目录。
4. 安装成功但看不到新入口：完全退出并重启 DSH；仍无则检查 -Profile 是否指向你正在使用的 profile。
5. “...”菜单没有“修改工作区”：确认插件已启用且 DSH 版本为 0.2.1-rc.2；该入口依赖前端 DOM 结构。
6. 卸载后仍留有工作区记录：state.json 仅是插件自己的记录文件，卸载不会自动删除；重新安装会继续使用，如需彻底清除可手工删除 <DSH_HOME>\multi-workspace 目录。
